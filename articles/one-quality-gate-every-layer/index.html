One Quality Gate for Every Layer: Coverage, Complexity and File-Size Limits in CI

Oselio Candido · Sep 2026 · Draft in progress

Quality rules that live in five different tools with five different configs get bypassed one noqa at a time. One gate engine, one thresholds file, one CI entry point — and the rule that no threshold is ever silenced, only fixed.

What this write-up will cover

  • The problem: quality checks scattered across tools, each with its own escape hatch.
  • Options considered: pre-commit hooks, per-tool CI jobs, a single gate engine as the authority.
  • Tradeoffs: local hooks vs CI as the source of truth; strictness vs contributor friction.
  • The decision: one CLI → gate → constants pipeline enforcing coverage ≥75%, zero lint/type errors, ≤500-line files, radon grade B.
  • Impact: what the gate has caught, and how 'fix the root cause' survives deadline pressure.
This article is being written. The decision has already been made in production — the write-up follows the same format as every other piece here: problem, options, tradeoffs, decision, measurable impact.
